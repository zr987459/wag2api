# wag2api

> **一个 App，两个 AI 网关引擎。**
> 把 **Google Antigravity（Cloud Code）** 与 **腾讯 WorkBuddy / CodeBuddy** 两条顶级上游，统一到同一个本地端口、同一套 API、同一个现代移动端控制台。

wag2api 让你手机或 Linux 服务器上持有的 Google 与腾讯上游账号，都能通过**统一的、标准的 OpenAI / Anthropic 协议接口**对外提供服务。它内置 Kotlin 高性能前门、智能三层分流、软拦截总开关、流式体检与双端点智能自愈回退——你只管接入使用，复杂路由与上游校验全由网关搞定。

## 核心特性

- 🔓 **纯净开源免激活**：完全开源免费，零授权码、零商业激活拦截、零外部云端依赖，100% 本地自洽。
- 🎯 **统一单端口入口**：对外唯一绑定 `127.0.0.1:8800`，一套 API 密钥统一调度 Google 与腾讯两大家族模型。
- 🧠 **双引擎平稳隔离**：
  - **WB 引擎 (Kotlin 原生)**：毫秒级启动，内存仅占数兆，完整支持 `/v1/messages` 与 `/v1/chat/completions`。
  - **AG 引擎 (Node.js 运行时)**：退居内部 `127.0.0.1:18790` 安全端口，原生支持 `/v1/messages`，具备强大的 `thinking` 与 `tool_use`。
- ⚡ **智能三层分流**：按「路径 ➔ 模型名前缀 ➔ 模型表精确匹配 ➔ 默认引擎」严格判定，绝不靠模糊猜词误路由。
- 🛡️ **网关软拦截总开关**：概览页一键启停网关，关闭时在前门实施平滑软拦截（明确返回 503 提示）并释放上游引擎与 WakeLock，通知栏动态联动。
- 🩺 **深度连通性体检**：每个账号卡片独立测活 + 调度池「全部测试」，强制采用流式模式（对齐上游 11101 要求）并注入全套客户端指纹，诊断结果秒变人话。
- 🔄 **凭据冷热流转**：支持单账号完整 JSON 独立导出备份，支持批量导入导出（与 CookieBox 格式无缝互通），支持粘贴裸 JWT 智能解析入库。
- 🔀 **双端点毫秒级智能自愈回退**：自动在 `/v2` 与 `/console` 之间自愈轮换，规避 11128 渠道拦截与腾讯云 WAF 403 阻断，中途 429 限流自愈重试。
- 💡 **Thinking 深度思考隔离**：按 `$uid:$tool_call_id` 精确隔离思考缓存，杜绝多账号轮询与多轮对话时思考混淆膨胀。
- 📱 **5-Tab 移动端 Web 控制台**：专为手机触屏打造的现代卡片流（概览、账号、接入密钥、即时流式对话、运行审计日志）。
- 📦 **Full / Lite 双规格**：固化永久签名密钥（`release.p12.enc`），CI 强制执行证书 SHA-256 校验，100% 杜绝覆盖安装签名冲突拦截。

## 智能三层分流机制

前门按三层严谨顺序判断，**绝不靠模型名前缀猜测**（两边均有 `claude-` 和 `gemini-` 家族模型，靠前缀猜测必然误伤）：

| 优先级 | 判定规则 | 匹配示例 | 路由去向 |
| :---: | :--- | :--- | :--- |
| **第 1 层** | **路径判定** | `/ag/*`、`/api/*` ➔ AG 引擎<br>`/panel/*`、`/m/*` ➔ WB 引擎 | 直接匹配路径转发，不解析 Body |
| **第 2 层** | **强制前缀** | `ag:gemini-3.8-flash` ➔ 去除前缀强制切 AG<br>`wb:deepseek-v4.1-flash-1017` ➔ 去除前缀强制切 WB | 显式指定最高优先级 |
| **第 3 层** | **模型表精确匹配** | 模型只在 AG 模型表（如 `claude-sonnet-4-6`）➔ AG<br>模型只在 WB 模型表（如 `hy4-preview`）➔ WB | 自动识别目标上游 |
| **兜底层** | **默认引擎** | 两边重名或客户端传入未知模型 | 按设置中选择的「默认引擎」兜底 |

- `GET /v1/models` 会合并返回双引擎的全量模型清单；对于重名模型会额外生成 `ag:` 与 `wb:` 别名供显式指定。

## 深度连通性体检（流式对齐 11101）

针对上游频繁更新防刷策略、传统非流式连通性测试频频误报的问题，系统内置了**工业级深度体检机制**：

1. **强制流式最小探测**：发起流式首帧测试，完美对齐腾讯上游 `11101` 强校验规则，彻底消灭“测试报失败但实际对话可用”的假阳性。
2. **全套客户端桌面指纹注入**：携带完整的官方客户端特征（`X-CodeBuddy-Request: 1`、`X-Conversation-ID`、`X-Machine-ID`、`X-Agent-Purpose` 等）。
3. **可视化诊断三态呈现**：
   - ✅ **连通正常**：展示毫秒级耗时与命中的真实上游端点；
   - ⚠️ **账号可用但上游繁忙 (429/14003)**：代表账号凭据与鉴权完全正常，仅上游服务器排队限流，可稍后重试；
   - ❌ **失败**：深度解析并翻译为人话提示（如「Token 已失效过期」、「渠道校验拦截」、「端点无法连通」）。
4. **一键体检**：支持单账号卡片独立测活，也支持顶部调度卡片「全部测试」批量轮询排查。

## 网关软拦截总开关

在概览页「服务设置」中提供了一键 **「网关总开关」**：

- **优雅软拦截**：关闭网关时，前门端口保持监听但不向下游投递请求，对客户端明确返回 `503 Service Unavailable (Gateway Disabled)`，防止客户端误判为网络掉线死等超时。
- **功耗与资源释放**：关闭时自动断开上游长连接并释放 CPU WakeLock 唤醒锁，待机零发烫零跑电。
- **状态栏联动**：通知栏文案随状态动态切换为「网关已关闭 · 点按打开」，点击常驻通知即可一秒唤醒进入面板重新开启。

## 双端点毫秒级智能自愈回退与反拦截

腾讯 WorkBuddy 官方存在 `/v2/chat/completions` 与 `/console/chat/completions` 两个通道：
- `/console` 通道对首包更宽容，但在长上下文出现 Linux 脚本命令（如 `/proc/`、`netstat` 等）时容易被腾讯云 WAF 拦截（返回 403 HTML 阻断页）；
- `/v2` 通道不易受 WAF 阻断，但在首句对话时容易触发 `11128` 渠道强校验。

**wag2api 智能自愈回退算法：**
1. 默认优先尝试主通道，并在首帧进行毫秒级嗅探；
2. 一旦捕获到 `11128` 错误，**0.1 秒内无感切换至备用通道重试**；
3. 一旦捕获到腾讯云 WAF 403 阻断，自动切换通道无感重试；
4. 遇到 429 或 `14003` 繁忙帧，自动映射为 Anthropic 协议标准的 `529 overloaded_error` 触发客户端无感重试机制；
5. 请求体历史中出现的裸数字 `11128` 自动改写为 `11-128` 脱敏，彻底根除上游反探测规则误杀。

## Thinking 思考隔离与工具调用闭环

- **思考按调用精细隔离**：网关以 `$uid:$tool_call_id` 建立两级索引缓存思考内容，彻底解决多账号轮询调度以及长轮次工具调用时，历史思考内容同构覆盖导致的上下文暴增问题。
- **工具调用闭环修复**：内置 `repairToolPairing` 机制，自动处理 user 消息与 assistant `tool_use` / `tool_result` 的配对与拆分，杜绝因工具未闭环导致的上游拒答。

## 账号资产管理：单码与批量导入导出

1. **单账号导出**：每个账号卡片均提供「导出」按钮，弹出独立 JSON（包含 uid、nickname、realm、accessToken、refreshToken），一键复制，轻松备份单个高等级账号。
2. **批量备份导入/导出**：支持与 CookieBox 工具链无缝互通的完整 JSON 格式，换机或重装时一键导入恢复全部账号资产。
3. **裸 JWT 极速解析**：支持直接粘贴腾讯官方授权取得的裸 JWT（`eyJ...`），网关自动解析出用户 ID、昵称和所属环境并平滑入库。
4. **安全底线**：所有凭据与 Token **仅保存在设备本地私有沙箱中**，绝对不向任何外部第三方服务器同步，安全无忧。

## 快速上手

### 一、Android 手机端

1. 在手机上打开 [Releases 最新发布页](../../releases/latest)，下载适合你的安装包并安装；
2. 打开 App，授权通知权限（用于状态栏常驻守护与自启动）；
3. **配置账号**：
   - 切换到底部「👥 账号」页 ➔ 点击「添加账号」完成官方授权登录，或点击「📥 导入」粘贴 JWT；
4. **验证连通性**：
   - 在卡片上点击「测试」按钮，看到绿色「✅ 连通正常」即代表全链路打通；
5. **获取接入地址**：
   - 切换到「🔑 接入」页，复制接口地址：`http://127.0.0.1:8800/v1` 及 API 密钥。

### 二、Linux 服务端

```bash
# 下载并解压单文件预编译包
xz -d wag2api-linux-x64.xz
chmod +x wag2api-linux-x64

# 启动运行（数据默认保存在 ~/.wag2api）
./wag2api-linux-x64
```

## 客户端接入配置示例

### 1. Claude Code / Anthropic 协议客户端
- **Base URL**: `http://127.0.0.1:8800` (或 `http://127.0.0.1:8800/v1`)
- **API Key**: 任意填写（或在控制台设置的密钥）
- **推荐模型**:
  - `claude-sonnet-4-6`（走 AG 引擎，超强推理）
  - `deepseek-v4.1-flash-1017`（走 WB 引擎，0.00x 免计费极速响应）

- **API 接口地址**: `http://127.0.0.1:8800/v1`

```bash
  -H "Authorization: Bearer 1234" \

  -d '{
    "model": "deepseek-v4.1-flash-1017",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": false
  }'
```

## 常见问题 (FAQ)

#### Q1: 遇到上游 `11128` 或 `11101` 报错怎么处理？
**A**: 不需要手动处理。wag2api 内置了双端点智能自愈与全套客户端桌面指纹，首帧探测到报错会在 0.1 秒内自动切入备用通道重试并完成响应。连通性测试中也已全量适配流式检测，确保与实际对话表现一致。

#### Q2: 连通性测试显示「⚠️ 账号可用但上游繁忙(429/14003)」代表什么？
**A**: 这表示你的账号有效性、Token 鉴权和客户端指纹校验**全部通过且成功握手**，只是腾讯云端该模型正在排队或限流。账号状态健康，稍等几秒后即可正常使用。

#### Q3: 覆盖安装新版本时提示“软件包与现有软件包存在冲突”？
**A**: 请确保下载的是本项目官方 Releases 页面构建的产物。自 v1.1.1 起，项目在云端 CI 中固化了永久签名证书并开启了证书指纹比对机制，今后所有新版本均支持无感平滑覆盖安装。

#### Q4: 手机锁屏或切换到后台时网关会被系统杀死吗？
**A**: 不会。wag2api 在 Android 端以 `specialUse` 前台服务运行，并适配了开机自动拉起（`BOOT_COMPLETED`）；在长请求输出期间会按需持有临时 WakeLock，而在待机时自动释放，兼顾常驻稳定性与极致省电。
